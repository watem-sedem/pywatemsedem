pywatemsedem Postprocessing

1. Introduction

This tutorial demonstrates how to use the PostProcess class from the pywatemsedem package to analyze and postprocess WaTEM/SEDEM model output data.

What you will do in this notebook:

  • Initialize a PostProcess object for a scenario.

  • Inspect routing outputs (full routing, missing-routing, non-river routing, and river-only routing vectors).

  • Explore sink-related vectors: sediment export to rivers, sewer inflow, and combined sinks.

  • Inspect ranked sediment-load outputs for prioritization.

  • Delineate and inspect point-of-interest (POI) subcatchments.

  • Delineate and inspect buffer subcatchments.

  • Identify and visualize priority subcatchments with two approaches:

    • top-n selection,

    • percentage-based selection using sedi_export + sewer_in.

  • Run and inspect the grass-strip postprocessing workflow.

All generated outputs are written to the postprocessing folder and can be inspected as GeoDataFrames or loaded in GIS.

Routing vectors

Prepare routing vectors as line shapefiles. Each line represents one source→target arrow with an extra sedi_out column (source sedi_out × part).

Available vectors:

  • vct_routing: full routing table (land + river arrows).

  • vct_routing_missing: routes that do not end in a sink (None if the routing_missing table has no lines).

  • vct_routing_non_river: routing arrows whose source is a land pixel (river arrows dropped).

  • vct_routing_river: routing arrows whose source is a river pixel.

Below only vct_routing_non_river is computed and inspected.

Priority areas

In this section, we identify priority areas: locations with the highest remaining source value, together with the subcatchment draining to each one. The subcatchment itself is not separately ranked – it is simply the drainage area coupled to its priority point.

The source value is the pixel value of the raster chosen with the source argument:

  • "sedi_out": sediment leaving the pixel (kg), including sediment routed into it from upstream.

  • "sedi_export": sediment exported from the pixel to a river (kg). It is only non-zero for pixels draining directly into a river.

  • "sedi_export + sewer_in": sediment exported from the pixel to a river or entering a sewer (kg).

“Remaining” means the pixel does not lie in the subcatchment of a priority picked earlier.

What happens step by step:

  1. We repeatedly pick the pixel with the highest remaining source value as a priority point, then mask out its contribution so it can’t be picked again.

  2. We delineate the subcatchment draining to each priority point and couple it to that point.

  3. The plot gives a quick visual overview of where the priority areas and the linked subcatchments are.

Both outputs carry a source_val column: the raster value of the point that made it a priority (not the subcatchment’s total contribution), and both are sorted from highest to lowest priority.

How to read the colors in the plot:

  • red = highest priority (id=1)

  • blue = lower priority

Below, we show two methods with the same structure so they are easy to compare.

Priority areas (approach 2: percentage, source = sedi_export + sewer_in)

This method keeps priority areas until cumulative contribution first exceeds the chosen threshold.

In practice:

  • source="sedi_export + sewer_in": combines contribution to rivers and sewers.

  • approach="percentage": keeps priority areas in priority order up to the first threshold crossing.

  • threshold=30: keeps the highest-priority areas until cumperc first goes above 30%.

In the geodata for this method, you also get cumperc:

  • cumperc is the cumulative contribution by priority level.

  • It helps you verify where the first threshold crossing happens.

[ ]:

# Percentage method: keep subcatchments until cumulative contribution first exceeds 30%
pp.identify_priority_areas(
    source="sedi_export + sewer_in",
    approach="percentage",
    threshold=30,
)
